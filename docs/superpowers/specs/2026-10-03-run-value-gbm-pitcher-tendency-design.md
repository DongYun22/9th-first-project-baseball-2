# 설계: Run Value 기반 GBM으로 회피형/승부형 투수의 판단 평가

2026-10-03. 새 노트북(`03_DY_run_value_gbm_pitcher_tendency.ipynb`) 설계입니다. 구현 계획은 이 문서 승인 후 따로 씁니다.

## 1. 배경과 질문

팀 회의 결론: 강화학습(RL)은 쓰지 않는다 — 모든 상황의 최적 구종을 찾는 쪽으로 가면 연구 주제가 "일반적인 구종 추천 모델"로 번질 위험이 있기 때문이다. 대신 **GBM 기반 Run Value 분석**으로, 다음 질문에 답한다.

> 장타를 맞은 구종을 이후 재대결에서 회피하는 것이, 투수에게 Run Value 기준으로 실제 유리한 선택인가?

핵심은 **개별 한 타석의 최적 구종**이 아니라 **회피 성향 자체가 장기적으로 좋은 선택이었는지**다. 그래서 GBM은 "이 한 타석에 뭘 던졌어야 했나"를 추천하는 모델이 아니라, 상황별 **기대 Run Value**를 계산하는 보정 기준선으로 쓴다. 이 기준선 대비 실제 결과(RVAE, 아래 5절)를 투수별로 모아, 회피율 그룹(3분위/2분위) 간 평균을 비교하는 것이 메인 결론이다. 개별 타석 반사실 비교(6절)는 그 보조 지표다.

## 2. 데이터

기존 노트북 01·02와 같은 방식으로 팀 공유 research CSV 6개(`data/research/`)를 직접 읽는다. `data/raw`, R/rpy2 둘 다 쓰지 않는다(이번 분석은 순수 Python/scikit-learn).

필요 컬럼: `game_pk, game_date, at_bat_number, pitch_number, pitcher, player_name, batter, stand, p_throws, pitch_type, events, balls, strikes, outs_when_up, inning, inning_topbot, on_1b, on_2b, on_3b, home_score, away_score, woba_value, woba_denom`.

**결정구(타석을 끝낸 투구)만 Run Value가 있다.** CSV 실측 확인 결과 `woba_value`/`woba_denom`은 그 타석의 마지막 투구에만 채워지고 그 전 투구는 비어 있다. 그래서 GBM의 학습·평가 단위는 **타석 하나가 아니라 그 타석을 끝낸 결정구 하나**다.

## 3. 투수별 회피율

### 3.1 정의
기존 노트북 01의 같은 타자 재대결 이벤트셋(장타 → 같은 타자 재대결, `reused_same_type`)을 그대로 재사용한다. 투수의 회피율 = `1 - mean(reused_same_type)`(그 투수의 재대결 이벤트들에서, 장타 맞은 구종을 타석 전체에서 한 번도 다시 안 던진 비율).

### 3.2 집계 단위: 투수 1명 (2021–2026 전체 합산), 단 먼저 시즌 안정성 검증
투수 단위는 시즌을 합쳐 한 명으로 잡는다(표본을 늘려 회피율·RVAE 추정을 안정시키기 위함). 다만 이렇게 합치는 게 타당한지 먼저 확인한다.

- **시즌별 회피율**: 투수-시즌 조합 중 그 시즌 재대결 이벤트가 5건 이상인 것만 계산.
- **안정성 검증**: 그렇게 구한 시즌별 회피율 중, 2개 시즌 이상 자격을 갖춘 투수만 모아 분산 분해를 한다 — 전체 분산 중 "투수 간 차이"가 설명하는 비율(η², 그룹=투수, 값=시즌별 회피율인 일원분산분석의 between-SS/total-SS)과, 같은 투수의 인접 두 시즌 회피율 산점도(상관계수 포함)를 함께 낸다.
- η²이 낮게 나와도(시즌마다 변동이 크다는 뜻) **진행은 그대로 한다**(이미 정하신 사항). 다만 그 수치를 한계로 명시하고, 결과 해석에서 "투수 성향이 시즌 간에도 어느 정도 일관된 특성"인지 "그때그때 다른 것"인지를 독자가 판단할 수 있게 한다.

### 3.3 분석 포함 기준
재대결 이벤트(전 시즌 합산)가 **10건 이상**인 투수만 회피율·RVAE 비교에 포함한다. 그 아래 표본은 회피율이 0%/100% 근처로 쏠려 비교가 왜곡된다.

### 3.4 그룹화
포함 기준을 만족한 투수들의 회피율로 **3분위**(하위=승부형, 상위=회피형, 중위 제외)와 **2분위**(중앙값 기준 회피형/승부형, 중립 없음) 두 가지를 모두 만든다. 이후 5·7·8절 분석을 두 그룹화 각각에 대해 반복한다.

## 4. GBM Run Value 모델

### 4.1 타깃
결정구의 `woba_value`(표본 전체의 모든 타석, 재대결에 국한하지 않음 — "이 상황·구종 조합의 일반적 가치"를 배우려면 넓은 모집단이 필요).

### 4.2 피처 (회의록 그대로)
`balls`, `strikes`, `outs_when_up`, 주자 상황(`runners_n`, `risp` — 노트북 01의 정의 재사용), `stand`, `p_throws`, `score_diff`(노트북 01의 `compute_score_diff` 정의 재사용), `pitch_type`(범주형), 그 투수·시즌·구종의 `season_usage_rate`(그 결정구가 일어난 시즌 기준, `avoidance_stats.compute_season_usage_rate` 재사용).

**`pitcher_id`는 피처에 넣지 않는다** — 그대로 넣으면 모델이 특정 투수를 외워버려(과적합) "상황·구종이 주는 일반적 가치"를 배우지 못한다. 대신 `season_usage_rate`로 "이 투수가 이 구종에 얼마나 의존/능숙한가"를 표현한다.

### 4.3 모델: scikit-learn `HistGradientBoostingRegressor`
이미 설치돼 있어 새 의존성이 없고(요청하신 "데이터에 적합한 모델"로 직접 판단), 범주형 피처(`pitch_type`, `stand`, `p_throws`)를 `categorical_features` 인자로 네이티브 처리할 수 있어 원-핫 인코딩이 필요 없으며, 학습 표본이 수십만–100만 행대라 히스토그램 기반 구현이 충분히 빠르다. 필요하면 나중에 XGBoost/LightGBM으로 교체 가능하도록 학습·예측 로직을 함수로 분리한다.

### 4.4 학습/검증
시즌을 기준으로 분할한다(예: 2021–2025로 학습, 2026으로 검증 — 시간 분할이 상황을 "미래 추정"하는 실제 쓰임에 더 맞고, 무작위 분할보다 낙관적 편향이 적다). 검증 세트에서 MAE와 베이스라인(전체 평균으로만 예측했을 때의 MAE) 대비 개선폭을 보고한다. 최종적으로 재대결 이벤트에 적용할 때는 전체 데이터(2021–2026)로 다시 학습한 모델을 쓴다.

## 5. 핵심 지표: RVAE (기대 대비 Run Value)

재대결 이벤트 중 `has_next_ab`(재대결 타석이 실제로 있음)인 것만 대상으로, **그 재대결 타석의 결정구**를 찾는다(그 타석에서 `woba_value`가 채워진 투구). 그 결정구의 상황·구종·구사율을 모델에 넣어 기대 Run Value를 구하고,

```
RVAE = 실제 woba_value − 모델 기대 Run Value
```

를 계산한다(낮을수록 투수에게 유리 = 기대보다 낮은 run value를 허용). 투수별로 평균 내어 `mean_RVAE`를 만든다.

**메인 결과**: 3.4절의 두 그룹화 각각에서, 회피형 vs 승부형의 `mean_RVAE`를 비교한다(Welch t-test, Mann-Whitney U — 기존 `summarize_diff_in_diff`와 같은 틀 재사용). 회피형의 평균 RVAE가 승부형보다 유의하게 낮으면 "회피 성향이 더 나은 장기 결과와 연관된다"는 근거가 된다. 반대면 그 반대로 해석한다. 유의한 차이가 없으면 "회피 여부 자체보다 다른 요인이 더 중요하다"로 읽는다.

## 6. 보조 지표: 레퍼토리 반사실 비교

RVAE는 "결정구가 어떤 구종이었든 기대 대비 얼마나 잘했나"만 본다. 이걸 보강하기 위해, 같은 재대결 이벤트에서 **그 투수의 그 시즌 레퍼토리**(시즌 구사율 **5% 이상**인 구종만 — 희귀 구종이 샘플 부족으로 "최적"으로 잘못 뽑히는 것을 막음) 안의 각 구종을 같은 상황 피처에 대입해 예측하고,

- `실제 선택의 예측값 − 레퍼토리 중 최솟값` = 그 결정이 레퍼토리 안에서 최선 대비 얼마나 손해였는지
- 실제 선택이 레퍼토리 중 최솟값과 같은 구종이었는지(최선 일치 여부)

를 이벤트마다 구해서, 투수별로 평균 낸다. 이것도 회피형/승부형 그룹 비교에 보조로 쓴다.

## 11. 한계

- 결정구의 Run Value는 그 전까지 같은 타석에서 던진 투구들의 영향도 섞인 결과다 — "그 구종 선택 하나만의" 순수 인과효과가 아니라, "그 상황에서 그 구종으로 끝난 타석들의 평균적 결과"라는 상관적 지표다.
- 레퍼토리 기준(구사율 5%), 포함 기준(재대결 10건), 시즌 안정성 포함 기준(시즌당 5건)은 모두 사람이 정한 경계값이며, 바꾸면 그룹 구성과 사례 선정이 달라질 수 있다.
- 시즌을 합쳐 투수 1명으로 보는 것은 표본을 늘리기 위한 선택이며, 3.2절의 안정성 검증 결과에 따라 그 타당성이 달라진다(η²이 낮으면 "회피 성향"이 투수의 안정적 특성이 아니라 시즌마다 바뀌는 상황 의존적 선택일 수 있다).
- `pitcher_id`를 피처에서 뺐기 때문에, 같은 구종·구사율이라도 투수별 구종의 실제 구위(구속·무브먼트·커맨드)는 모델이 구분하지 못한다. `season_usage_rate`가 그 대리 변수 역할을 하지만 불완전하다.
